Reversa Optimize (Desempenho & Queries SQL)

OPP-20260829-cl3o: Eliminação de Queries N+1 no ClienteSerializer

Contexto: clientes | Alvo: backend/apps/clientes/serializers.py (ClienteSerializer)

1. Gargalo Identificado

N+1 Queries Múltiplas por Registro: Para cada cliente retornado, get_aceite_token, get_aceite_expira_em e get_aceite_usado executam independentemente obj.aceite_links.order_by("-criado_em").first(), ignorando prefetch e gerando 3 queries SQL redundantes por cliente. Além disso, contagens de contratos e usuários disparavam consultas adicionais.

Complexidade antes: O(N × 7 queries) no banco.

2. Otimização Proposta

In-Memory Prefetch & Instance Cache: Criar método auxiliar _get_ultimo_aceite_link que aproveita prefetch em memória ou cacheia a consulta na instância. Utilizar coleções já carregadas em memória para contagens e saldo.

Complexidade depois: O(1) queries adicionais.

3. Comparação de Execução

# ANTES:
get_aceite_token -> SQL SELECT ... (Query 1)
get_aceite_expira_em -> SQL SELECT ... (Query 2)
get_aceite_usado -> SQL SELECT ... (Query 3)
get_total_contratos -> SQL COUNT ... (Query 4)
get_contratos_ativos -> SQL COUNT ... (Query 5)

# DEPOIS:
_get_ultimo_aceite_link -> Reutiliza cache do prefetch (0 queries extras)
get_total_contratos -> len(obj.contratos.all()) em memória

4. Rede de Segurança e Preservação

Coberto por testes de listagem e serialização em test_clientes_e_usuarios.py (15 testes verdes).
